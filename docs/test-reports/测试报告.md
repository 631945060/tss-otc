# 测试报告

测试对象为 Go 服务端与 tss-lib 门限密码模块。运行以下命令可重复执行全部测试：

```bash
go test ./... -count=1
```

测试覆盖三个层面：RESTful 接口与审批状态机（20 条编号用例）、tss-lib 参数核验与 3 节点分布式密钥生成/任意 2 节点协作签名集成测试、以及 10/25/50/100 并发会话创建压力测试。

## 二、门限参数与集成测试

`signer/tss-common/parameters` 核验三个参与方、库门限参数 `threshold=1` 映射为 2-of-3 策略（库门限为多项式阶数，`threshold+1` 个参与方协作）。

`signer/tss-common/protocol` 的 `TestKeygenThenTwoPartySign` 执行一次 3 节点分布式密钥生成，随后对三组两方组合分别执行多轮签名并以 DKG 公钥执行 ECDSA 验签：

| 组合 | 结果 |
|---|---|
| node1 + node2 | ECDSA 验签通过 |
| node1 + node3 | ECDSA 验签通过 |
| node2 + node3 | ECDSA 验签通过 |

该测试说明门限签名是多轮协议协作输出同一签名，而不是收集两份独立签名后简单聚合；测试全过程不调用明文完整私钥重构接口。

## 三、并发会话创建压力测试

`apps/tss-wallet-service/internal/transport/httpapi/concurrency_test.go` 在同一进程内同时发起 10、25、50、100 个会话创建请求，记录延迟、吞吐量、失败数与 Go 堆内存增量。最近一次运行结果：

| 并发数 | P50 | P95 | P99 | 吞吐量 | 失败数 | 堆内存增量 |
|---|---|---|---|---|---|---|
| 10 | 1.160 ms | 1.198 ms | 1.198 ms | 7238.9 req/s | 0 | 245456 B |
| 25 | 24.875 µs | 82.416 µs | 90.667 µs | 134499.0 req/s | 0 | 277128 B |
| 50 | 29.541 µs | 110.459 µs | 137.667 µs | 198543.5 req/s | 0 | 552584 B |
| 100 | 22.5 µs | 111.625 µs | 157.833 µs | 225861.1 req/s | 0 | 1056616 B |

该结果仅反映本地进程内 HTTP 状态机与内存会话创建，不构成网络部署、数据库访问或 100 组完整门限 ECDSA 协议的容量结论。

## 结论

在本地所设测试场景下，20 项功能用例全部通过，3 组两方门限签名集成测试均通过 ECDSA 验签，10/25/50/100 并发会话创建无失败。测试结果支持“本地演示环境满足预定功能与性能要求”的结论，不等同于生产环境安全证明或完整密码学协议容量验证。
